# 대화 영역 좌우 여백

상태는 결정 필요입니다. 터미널 창 안에서 대화 내용과 가장자리 사이의 거리를 조절합니다. 터미널 앱이 포인트 단위로 제공하는 창 여백과 구분하며, Codex에서는 열 단위를 사용합니다. [전체 목록](README.md)의 두 번째 기능입니다.

## 제안 동작

왼쪽과 오른쪽 여백을 독립된 0 이상의 정수로 지정하고, 기본값은 0으로 둡니다. 설정 이름은 설계 단계에서 확정합니다. 대화 영역의 가용 폭에서 두 여백을 제외한 뒤 본문 최대 폭을 적용합니다.

160열 화면에 좌우 4열씩을 지정하면 대화 영역은 152열입니다. 답변 접두부와 블록 들여쓰기를 추가로 반영하며, 본문 최대 폭 80열은 그 안에서 적용합니다. 표·코드는 본문 제한 대신 여백 안의 가용 폭을 사용합니다.

## 할 것

- [ ] 본문·표·코드·사용자 메시지의 공통 대화 영역을 정의합니다.
- [ ] 너비뿐 아니라 내용의 시작 좌표를 함께 계산합니다.
- [ ] 좁은 화면에서 여백을 축소하여 내용을 표시할 공간을 확보합니다.
- [ ] 선택·링크 클릭·검색 강조·스크롤·복사의 좌표를 같은 배치 기준에 맞춥니다.
- [ ] 화면 크기 변경 시 배치와 캐시를 갱신합니다.

## 하지 않을 것

터미널 창 자체 여백·글꼴·픽셀 간격·가운데 정렬은 변경하지 않습니다. 여백을 원문에 공백으로 삽입하지 않습니다. 메뉴·승인 팝업·전체 상태 영역에 일괄 적용하지 않습니다.

## 결정할 사항

- [ ] 입력창을 대화 영역과 같은 좌우 경계에 맞출지 결정합니다. 적용하면 입력 커서와 자동완성 위치도 함께 변경합니다.
- [ ] 도구 출력과 diff에 같은 여백을 적용할지 결정합니다.
- [ ] 좁은 화면의 최소 가용 폭과 좌우 여백 축소 순서를 정합니다.
- [ ] 첫 버전을 전체 화면에 한정할지, 일반 모드에서도 제공할지 결정합니다.

## 선행 작업과 구현 영향

본문 최대 폭의 가용 폭 정의를 먼저 확정합니다. `chatwidget/rendering.rs`, `transcript_view`의 배치·선택·검색, `app/history_ui.rs`의 출력 경로를 조사합니다. 입력창까지 포함하면 `bottom_pane`의 별도 작업 지침도 확인합니다.

## 완료 기준

- [ ] 기본값 0에서 기존 배치가 동일합니다.
- [ ] 좌우 대칭·비대칭 여백과 본문 폭 조합이 정의한 위치에 표시됩니다.
- [ ] 좁은 창에서 내용과 필수 조작 영역이 사라지지 않습니다.
- [ ] 표시 위치와 선택·링크·검색 위치가 일치하고 복사 원문에는 여백이 들어가지 않습니다.
- [ ] 지원하는 화면 모드와 지원하지 않는 모드를 명시합니다.
- [ ] 검사·실제 화면 결과와 미확인 경로를 기록합니다.

## 제거 조건

업스트림에서 같은 대화 영역 여백과 좌표 처리를 제공하면 설정 이전 가능성을 확인한 뒤 통합 또는 제거합니다.
