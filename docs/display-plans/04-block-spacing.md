# 문단과 목록 사이 간격

상태는 검토 예정입니다. 내용 블록 사이의 빈 줄을 조절해 읽기 편한 정도와 화면에 보이는 정보량을 선택하도록 합니다. 터미널 셀의 실제 줄 높이를 조절하는 기능은 제외합니다. [전체 목록](README.md)의 네 번째 기능입니다.

## 기존 구조와 제안

`tui/src/markdown_render/list_spacing.rs`에는 생성 중의 `Compact`, 여러 줄 목록의 간격을 맞추는 `Uniform`, 일반 스크롤백의 `AfterMultiline` 정책이 있습니다. 본문 폭을 줄이면 목록이 여러 줄이 되어 기존 정책의 빈 줄도 달라질 수 있습니다.

기존 정책을 기준값으로 유지하고, 사용자 옵션은 기존 간격·좁은 간격·넓은 간격 같은 소수의 선택지부터 검토합니다. 실제 이름과 빈 줄 수는 비교 결과를 보고 결정합니다.

## 할 것

- [ ] 문단·목록 항목·인용·표·코드 경계의 기존 빈 줄 규칙을 조사합니다.
- [ ] 본문 최대 폭 변경만으로 생기는 간격 변화를 먼저 비교합니다.
- [ ] 조절할 블록 경계를 명시하고 원문 빈 줄과 표시용 빈 줄을 구분합니다.
- [ ] 생성 중에서 완료 상태로 전환할 때 스크롤 위치를 유지합니다.
- [ ] 표시용 빈 줄이 복사 원문과 검색 결과를 바꾸지 않도록 합니다.

## 하지 않을 것

원문 Markdown의 빈 줄을 수정하거나, 코드 내부 빈 줄·표 행 높이·글꼴 줄 높이를 일괄 변경하지 않습니다. 첫 버전에서 모든 블록의 간격을 개별 숫자로 지정하는 설정은 추가하지 않습니다.

## 결정할 사항

- [ ] 문단과 목록 간격을 하나의 설정으로 묶을지 분리할지 결정합니다.
- [ ] 생성 중에도 선택한 간격을 적용할지, 완료 후 간격과 구분할지 결정합니다.
- [ ] 인접 코드·표·인용의 경계를 조절 대상에 포함할지 결정합니다.
- [ ] 한 줄 목록과 여러 줄 목록의 차이를 유지할지 결정합니다.

## 선행 작업과 구현 영향

본문 최대 폭이 목록 줄 수에 미치는 영향을 먼저 확인합니다. 목록 정책, Markdown 블록 경계, 스트리밍 확정 시점, 전체 화면의 줄 수·스크롤 기준·캐시를 함께 검토합니다. 여백이나 가운데 정렬은 필수 선행 작업이 아닙니다.

## 완료 기준

- [ ] 기본 설정에서 기존 간격이 유지됩니다.
- [ ] 선택한 정책이 정의한 블록 경계에만 적용됩니다.
- [ ] 생성 중·완료 후·재개·창 크기 변경에서 누락·중복·예상 밖 빈 줄이 없습니다.
- [ ] 복사 원문·코드 내부 공백·검색이 유지됩니다.
- [ ] 간격 변화에도 현재 보고 있는 내용과 스크롤 위치를 유지합니다.

## 제거 조건

업스트림에 같은 사용자 간격 정책이 추가되면 기본 동작과 스트리밍 전환을 비교하여 통합 또는 제거합니다.
